# with 语句

**一句话解释**：凡是"**打开 → 使用 → 关闭**"这种三明治结构，都该用 `with`——它把 `try / finally` 里那个"最后一定要收尾"的部分自动化了。

## 它在替谁干活

不用 `with` 的时候，打开一个文件要写成：

```python
try:
    f = open("test.txt")
    # 用它
finally:
    f.close()      # 一定要关
```

用 `with`，同样的事一行：

```python
with open("test.txt") as f:
    # 用它
```

**区别在于收尾是否会被跳过。** 中间一旦抛出异常，`f.close()` 那一行就走不到了；`with` 保证无论正常结束还是异常退出，收尾都会执行。

## 一句判断规则

> 打开、使用、关闭——三明治结构，就用 `with`。

不必记哪些对象支持它，只要认得出这个结构（文件、数据库连接、网络会话、锁），就默认用 `with`。

## 它不管什么

这是最容易被搞混的一点：

**`with` 只保证"用完一定关"，不保证"文件存在"。**

文件不存在时，`open()` 在进入 `with` 之前就抛错了，`with` 根本不成立。那一层要由 `try / except` 去兜。

```python
try:
    with open("test.txt") as f:
        print(f.read())
except OSError as e:
    print(f"读取文件出错：{e}")
```

两层的分工很清楚：

| 层 | 负责 |
|---|---|
| `try / except` | 出错时**不让程序死**，给出可读的提示 |
| `with` | **用完一定关闭**，异常路径也不漏 |

**两个都要，缺一个都留口子。**

## 为什么"一定关闭"值得单独一个语法

因为不关的后果是隐性的：文件句柄被占用，后面再往同名文件写入会冲突；连接不释放，池子会被耗尽。这类错误不会在你写的那一行报出来，会在几十行之后以完全无关的样子出现。

**用一个语法把这些延迟报错消灭掉，是语言设计上的划算买卖。**

## 生活类比

借了图书馆的书。`try/finally` 是"记得还，忘了就罚款"；`with` 是"进出闸机自动登记"，你走神了它也给你销账。但它管不了"这本书在不在馆里"——那是另一件事。
