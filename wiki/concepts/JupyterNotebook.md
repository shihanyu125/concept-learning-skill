# Jupyter Notebook

## 一句话

Notebook 是一种**既是笔记、又是程序**的文件：同一份文档里既有能直接运行出结果的代码，也有给人看的文字说明，一段一段写、一段一段跑。

## 核心机制

### 文件与内核

- 文件后缀是 **`.ipynb`**，用编辑器打开后就能写、能跑；
- 运行代码需要一个**内核**，也就是背后实际执行代码的 Python 环境；一台机器上可能装了多个 Python 版本，要**显式挑一个**；
- 内核是**无状态**的：重启内核之后，之前定义的变量和内存里的内容全部消失，需要从头运行。

**内核与环境一旦不一致，就会出各种莫名其妙的错**，所以"我到底在用哪个环境"是必须弄清楚的第一件事。

### 两种单元

| 单元 | 用途 | 表现 |
| --- | --- | --- |
| **代码单元** | 写可执行的语句 | 点运行后直接出结果 |
| **Markdown 单元** | 写纯文本说明 | 负责排版与叙述，不执行 |

一份好的 Notebook，是**文字负责讲清思路、代码负责验证思路**，交替出现。它天然适合边学边记。

### 为什么它适合学习与数据分析

- **可分步**：不必一次跑完整个程序，可以一行一行试；
- **结果可见**：运行结果直接留在页面上，可以边看边改；
- **可复现**：文档本身就是操作记录，别人打开就能按同样顺序跑一遍；
- **可解释**：代码旁边的说明和结论是同一份文件，不会"代码在一边、分析在另一边"。

另一种形态是传统**脚本**，后缀 `.py`，整体一次性运行。两种都要会，但学习阶段 Notebook 更顺手。

## 生活类比

**带批注的实验记录本。** 传统脚本像一份打印好的实验流程，要改就得整份重来；Notebook 像一页一页的实验记录——这一页写操作，下一页贴结果，再下一页写"我刚才试错了，原因是……"。重新做实验时，翻到哪页跑哪页。

至于内核，相当于**实验台上的东西**：台面一清（重启内核），摆在上面的样品全没了，你得重新摆一遍。

## 常见坑

| 现象 | 原因与解法 |
| --- | --- |
| 运行结果和屏幕上写的不一样 | 编辑内容没保存，运行的是上一次保存的版本——**打开自动保存** |
| 报错说找不到某个包 | 缺运行所需依赖，按提示安装即可 |
| 越跑越乱、结果对不上 | 内核里残留了旧变量，**重启内核**后从头运行一遍 |
| 路径相关报错 | 目录或文件名里带中文，某些包会直接报错——**路径尽量只用英文** |
