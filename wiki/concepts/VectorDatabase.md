# VectorDatabase（向量数据库）

## 定义

向量数据库是**专门存储"向量"、并按"意思有多接近"来检索的数据库**。

一句话对照：普通数据库按"字面是否完全相同"精确查找；向量数据库把"意思相近"的东西找出来——**即使一个字都不重样**。

## 核心机制

- **向量（Vector / Embedding）**：用模型把一段文字或一张图片转成一组数字（例如 1536 个），这组数字"代表"它的含义。含义越接近，两个向量在空间里越靠近。
- **相似度搜索**：用"距离"衡量两个向量有多接近（常用余弦相似度、欧氏距离），找出与查询向量最接近的一批。
- **为什么普通数据库不行**：普通数据库只会精确匹配（如 `WHERE name = 'xx'`），它"不懂"什么叫意思相近。向量数据库用**近似最近邻（ANN）**算法，能在几百万条向量里快速找出"最像"的。

流程示意：`文本 → 嵌入模型 → 向量 → 存入索引 → 查询时算距离 → 返回最近的 Top-K`

## 使用边界（易混淆点）

- **不是普通数据库的替代品**：前者做语义相似查找，后者做精确查找与事务处理，实际系统里常配合使用。
- **不是大模型**：它自己不生成任何文字，只负责"把向量存起来、按相似度找出来"。
- **检索是"近似"的**：可能漏掉或找偏。高要求场景常配合关键词检索（混合检索）或重排序（rerank）。
