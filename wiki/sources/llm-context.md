## Summary

说明"上下文窗口"是什么、用什么计量、超限会怎样。核心结论：上下文是模型单次请求里**能看到的全部内容**的容量上限，以 token 计量；装不下的部分会被截断，模型相当于"忘了"。它不等于长期记忆。

## Key Claims

- 上下文窗口 = 单次请求可用的最大 token 总量，包含输入 token、输出 token，部分模型还含推理 token。
- 计量单位是 token（词元）。粗略估算：英文 1 token ≈ 0.75 个单词（约 4 个英文字符）；中文一个常用汉字通常对应 1–2 个 token，取决于分词方式。
- 超出上限会**截断（truncated）**：最早的内容被挤出去，这是长对话里 AI"选择性遗忘"的常见原因。
- 不同模型窗口不同，例如 gpt-4o 是 128k token。
- 上下文 ≠ 长期记忆：前者是"这一次对话当下能看到"，用完即散；后者跨对话持久保存。
- 上下文窗口 ≠ 输出长度：窗口是"输入 + 输出 + 推理"的总和。
- 使用边界：上下文空间有限且宝贵，塞太多无关资料会挤掉关键信息，应精简地喂信息而不是一股脑全丢。

## Key Quotes

> **生活类比：** 上下文像一张**固定大小的草稿纸 / 工作台**……台子就那么大，东西一多，最早摆上去的就被挤下去了。（原资料）

> 我理解上下文有两个鲜明的特点。一个是"平等"——窗口里装进去的每一条信息，AI 都一视同仁地记住……另一个是"有容量"——它就像一张大小固定的草稿纸。（学习者批注）

> 我对照 OpenAI 的官方文档核查过，纠正了自己的一个误区——原来我容易把"上下文"直接当成"记忆"，现在明白它只是单次对话的临时窗口。（学习者核查笔记）

## 学习者的疑问（待后续资料回答）

既然上下文有容量限制，那市面上说"能记住你的偏好"的 AI，到底靠的是长期记忆机制，还是每次重新把历史塞进上下文？

**目前进展（2026-09-13，本页重新摄取时）**：wiki 已建起 [[Memory]] 页，给出了判断框架——**模型本身是无状态的，任何"记住"最终都必须表现为"该内容又回到了上下文里"**；所以"长期记忆机制"与"重灌上下文"并非对立的两条路，而是同一条路上的两种存储与取回安排。

**进展（2026-09-13）**：三层记忆的分工给出了具体答案——**不存在"凭空记住"**：所谓记住，要么是内容被写进持久层、之后被**取回**进上下文（用户级 / 工作区记忆），要么是系统在服务端维护一份画像、每次对话重新注入（云端记忆）。**两者是同一机制在不同存储位置上的安排**，不是两种神秘能力。详见 [[Memory]] 的"记忆分三层"。

**状态：已实质回答。** 唯一保留的是"人的验证"——本 wiki 依据来源做出的这层推论，尚未与厂商一手文档对照，按 `human owns verification` 原则仍不作定论。见 [[overview]] 的"已知的空白"。
