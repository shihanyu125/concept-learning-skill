Skill（技能）

用 AI 生成并经本人核查的学习资料 · 可复用 Skill：concept-learner 产出

学习目标

学完这个概念，你应该能做到：

  • 说出 Skill 是什么、它和「一次性提示词」的区别
  • 理解 SKILL.md 顶部 YAML 元数据（name / description）的作用
  • 解释什么是「渐进式披露」

核心问题

带着这个问题读下面的内容：AI 是怎么「按需」学会新技能的？Skill 为什么能反复复用？

1一句话解释（我的理解）

Skill 是一个「打包好的专业能力文件夹」——里面装着指令、脚本、资源。AI 平时是个「全能但泛泛」的助手，一旦遇到相关任务，才打开对应的 Skill，让自己临时变成这个领域的专家。

生活类比：Skill 就像给新员工的一套「入职手册 + 工具包」。AI 平时啥都能干但都不精；当任务涉及 Excel，它就翻开「Excel 技能包」，照里面的说明和工具操作，瞬间变成 Excel 高手。平时这套手册收在柜子里，不占地方。

2核心机制 / 组成

  • Skill = 一个文件夹，核心是一个 SKILL.md 文件，里面写着指令，旁边还可以带脚本、资源文件。
  • SKILL.md 顶部必须有 YAML 元数据，至少写 name（名字）和 description（描述）——这是技能的「名片」，AI 启动时先预读这些，用于判断「什么时候该用这个技能」。
  • 渐进式披露（progressive disclosure）：AI 不会一次读完所有技能，而是分三层按需加载——先看所有技能的 name+description（判断用哪个）→ 确定相关后读该技能的 SKILL.md 全文 → 需要时再读它引用的额外文件。这样既省空间又高效。
  • 四大特点：可组合（composable）、可移植（portable）、高效（efficient）、可含可执行代码（powerful）。
一句话记住：Skill 把「怎么做好某件事」的方法，沉淀成一个可反复调用、按需加载的知识包。

3一个具体应用场景

本仓库里的 concept-learner 就是一个 Skill：它把「如何学透一个概念」的方法（先定义、再拆机制、给案例、辨析边界、出自测题、查来源）打包成了可复用流程。以后你遇到任何新概念——比如「向量数据库」「正则表达式」——只要把概念名喂给它，就能复用同一套步骤生成学习资料，而不是每次重新写一遍提示词。

4容易混淆的点 / 使用边界

  • 易混淆：Skill ≠ 模型本身。Skill 不是一个新的 AI，而是「装在 AI 上、让它更擅长某件事」的说明书和工具。
  • 易混淆：Skill ≠ 一次性提示词（prompt）。提示词是「一段话、用完就散」；Skill 是「结构化的、可复用、按需加载」的能力包，能沉淀、能迭代、能分享。
  • 使用边界：Skill 依赖 AI「决定何时加载」，所以 name 和 description 如果写得太模糊，AI 可能在该用时没触发；写好元数据是让 Skill 生效的关键。

5自测题（检验是否真懂）

Q1：SKILL.md 文件顶部必须包含什么？
A：YAML 元数据（frontmatter），至少写明 name 和 description。
Q2：什么是「渐进式披露」？
A：按需逐层加载信息——先读 name+description，确定相关后再读全文，需要时再读引用文件。
Q3：Skill 和「一次性提示词」的本质区别？
A：Skill 是结构化、可复用、按需加载的能力包；提示词是一段话、用完即散。

7我的理解与核查笔记（本人填写）

我的理解：说实话，在做这个作业之前，我对 Skill 和提示词的区别也不太分得清。但亲手做完 concept-learner 这个 Skill 之后，我大概明白了：提示词就像「随口说的一句话」，说一次就没了，下次还得重新组织语言；而 Skill 就像「做好的一套模板工具」，把「怎么学透一个概念」的整套方法固定下来，下次想学别的概念，直接把概念名塞进去就行，不用从头写一遍。它像给 AI 配了一本「专用说明书 + 工具包」，平时收着，需要的时候才翻开。

核查与修改：我对照 Anthropic 的《Introducing Agent Skills》，明白了 SKILL.md 顶部那个 YAML 元数据（name 和 description）的作用——它像技能的「名片」，AI 靠它判断「什么时候该用这个技能」。这也让我明白 description 一定要写清楚，写模糊了 AI 可能根本不会触发。

我的疑问：我还没完全想通：Skill 和「提示词」之间到底有没有一条明确的界线？比如我把一段很长的提示词存成一个文件，算不算也是一种 Skill？
