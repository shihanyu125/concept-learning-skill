大模型的上下文（Context / Context Window）

用 AI 生成并经本人核查的学习资料 · 可复用 Skill：concept-learner 产出

学习目标

学完这个概念，你应该能做到：

  • 解释「上下文窗口」是什么、用什么单位（token）计量
  • 说清「上下文」和「长期记忆」的区别
  • 理解「超过窗口会截断 / 遗忘」是什么意思

核心问题

带着这个问题读下面的内容：模型为什么聊着聊着会「忘事」？它一次到底能「记住」多少？

1一句话解释（我的理解）

上下文，就是大模型在回答你之前「一次性能看到的全部内容」的容量。你发给它的问题、之前的对话历史、你喂给它的资料、以及它正在生成的回答，全都要装进一个固定大小的「窗口」里；窗口装不下的，它就看不见了。

生活类比：上下文像一张固定大小的草稿纸 / 工作台。你让 AI 写文章，它得同时看着你的要求、之前聊过的内容、参考资料、正在写的部分——这些东西全摊在台子上。台子就那么大，东西一多，最早摆上去的就被挤下去了。

2核心机制 / 组成

  • 计量单位是 token（词元）：模型把文本切成最小单位来处理。粗略估算，英文里 1 个 token 大约对应 0.75 个单词（约 4 个英文字符）；中文里一个常用汉字通常对应 1~2 个 token，具体取决于模型的分词方式。
  • 上下文窗口（context window）= 单次请求能用的最大 token 总数，通常包含三类：输入 token（你给的）+ 输出 token（模型生成的）+ 部分模型的推理 token（模型「思考」用的）。
  • 超限会截断：一旦内容超过窗口上限，最早的内容会被「挤出去」，模型就相当于「忘了」它们（官方叫 truncated）。
  • 不同模型窗口大小不同，例如 gpt-4o 的上下文窗口是 128k token。
窗口大小决定了 AI 一次能「记住多少」。这也是为什么聊得越久、内容越多，AI 会开始「选择性遗忘」最早的内容——窗口满了。

3一个具体应用场景

对话里的「上下文用量」：你之前在用 AI 时看到每个聊天框都有一条「上下文用量」进度条，指的就是这个——我们聊的每一句、中间跑的每一条命令，都在占用这张「草稿纸」。当它快满时，AI 就会优先记住最近的对话、淡忘最早的一些细节。

4容易混淆的点 / 使用边界

  • 易混淆：上下文 ≠ 长期记忆。上下文是「这一次对话当下能看到的」，用完即散；长期记忆是「跨对话持久保存」的，两者不是一回事。
  • 易混淆：上下文窗口 ≠ 输出长度。窗口是「输入+输出+推理」的总和，不只是模型能写多长。
  • 使用边界：上下文空间有限且宝贵，塞进太多无关资料会挤掉关键信息，所以要学会「精简地喂给模型信息」，而不是一股脑全丢进去。

5自测题（检验是否真懂）

Q1：「上下文窗口」到底是什么？
A：单次请求可用的最大 token 总量，包含输入 token、输出 token（和部分模型的推理 token）。
Q2：token 是什么？
A：模型切分文本的最小单位，模型用它来计量输入和输出。
Q3：内容超过上下文窗口会怎样？
A：会被截断，最早的内容被「挤出去」，模型相当于遗忘了它们。

7我的理解与核查笔记（本人填写）

我的理解：我理解上下文有两个鲜明的特点。一个是「平等」——窗口里装进去的每一条信息，AI 都一视同仁地记住，不会像人脑那样只对某些事印象深、把别的淡忘。另一个是「有容量」——它就像一张大小固定的草稿纸，装满了最早的内容就会被挤出去、相当于忘了，这一点挺让人遗憾的。读完后我也分清了：上下文是「这一次对话当下」能看到的，用完即散；而「长期记忆」是能跨对话一直保存的东西，两者不是一回事。

核查与修改：我对照 OpenAI 的官方文档核查过，纠正了自己的一个误区——原来我容易把「上下文」直接当成「记忆」，现在明白它只是单次对话的临时窗口，超过上限会被截断（truncated），并不是真正的长期存储。

我的疑问：既然上下文有容量限制，那市面上说「能记住你的偏好」的 AI，到底靠的是长期记忆机制，还是每次重新把历史塞进上下文？
