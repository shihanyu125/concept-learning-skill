Agent（智能体）

用 AI 生成并经本人核查的学习资料 · 可复用 Skill：concept-learner 产出

1一句话解释（我的理解）

Agent 是一个「能自己拿主意、自己动手做事」的 AI 程序。普通聊天机器人只能回答你问题；而 Agent 会在接到一个目标后，自己拆步骤、自己决定下一步干什么、自己调用工具，一步步把目标完成。

生活类比：普通 AI 像一位「只会给你建议的顾问」——你问它「怎么订机票」，它告诉你步骤，但不动手。Agent 则像一位「能直接替你办事的助理」——你说「帮我订张明天的机票」，它自己查航班、比价格、下单、确认，全程不用你一步步指挥。

2核心机制 / 组成

一个 Agent 的内核，是一个「被增强的大语言模型（LLM）」，在模型之上叠加了三种能力：

  • 检索（Retrieval）：能去外部查资料、查数据，不是只靠脑内记忆。
  • 工具（Tools）：能调用外部工具——搜网页、跑代码、查数据库、发邮件等。
  • 记忆（Memory）：能记住对话过程和中间状态，跨步骤保持连贯。

理解 Agent 最关键是区分它与「工作流（Workflow）」——这是 Anthropic 官方文章反复强调的核心：

工作流 Workflow智能体 Agent
控制权在谁代码（预先写死流程）模型（自己动态决定）
类比有轨列车，轨道提前铺好自动驾驶汽车，按路况变路线
优点稳定、可预测、易调试、省钱灵活、能应对开放复杂任务
缺点只能处理固定流程不确定、可能无效循环、更费 token、难排查

3一个具体应用场景

自动整理邮箱的 Agent：你设定一个目标「帮我整理今天的邮件」，Agent 会自己读取收件箱 → 判断每封是垃圾、广告还是重要事务 → 垃圾的归档、广告的打标签、重要的自动起草回复并提醒你确认。整个过程它自己规划、自己调用「读邮件」「分类」「归档」等工具完成，你只看结果。

4容易混淆的点 / 使用边界

  • 易混淆：不是「只要调用了工具的 AI」就叫 Agent；很多自动化脚本也会调工具，但流程是写死的，那是 Workflow 不是 Agent。
  • 易混淆：不是「越自主越好」。Anthropic 的结论是：能用简单方案解决就不要上 Agent——简单任务用一次普通 AI 调用就够了，盲目上 Agent 只会更贵、更慢、更不可控。
  • 使用边界：Agent 适合「目标开放、步骤无法提前枚举」的任务；对于「步骤固定、结果可预测」的任务，Workflow 或直接调用反而更好。

5自测题（检验是否真懂）

Q1：Workflow 和 Agent 最本质的区别是什么？
A：控制权在谁手里——Workflow 由代码预先定流程，Agent 由模型自己动态决定下一步。
Q2：Agent 的三种核心增强能力分别是什么？
A：检索（Retrieval）、工具（Tools）、记忆（Memory）。
Q3：什么样的情况下「不该」使用 Agent？
A：任务简单、步骤固定、可预测时，用简单方案（一次 LLM 调用或 Workflow）即可，无需 Agent。
